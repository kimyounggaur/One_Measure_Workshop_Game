# S05 — Transactional editing and session state

Date: 2026-10-19. Status: **AUTO_PASS**, browser adapters and device checks belong to later stages. Root explicitly approved the S04 gate before implementation began. The six content oracle sets and answer counts were not changed.

## Implemented

- `src/domain/commands.ts`: place, move, resize, delete, replaceKind, splitAndRearticulate, mergeAdjacentRests, fillGapsWithRests, clear, undo, redo, setTempo, setTitle. Every candidate passes document schema and authoritative puzzle edit validation before committing. Failure returns the identical editor state, preserving revision and both history stacks. Successful changes, including undo/redo, increment revision monotonically.
- History contains complete document snapshots, retains at most 100 commands, restores event IDs and metadata exactly, and discards redo on a new edit. Undo does not rewind the revision counter. An unchanged command commits zero times. `updatedAt` is a caller-supplied intent timestamp; omitting it retains the existing timestamp, keeping the command pure.
- Move checks the document after replacing its old position. No overwrite, pushing, automatic rest creation, or note merge. Split preserves length and adds a note onset; rest split preserves silence. Rest merge only accepts adjacent supported totals. L2 clear preserves authoritative locked originals. Free-only fill previews, then commits largest-fitting rests left-to-right in one undo step.
- `src/app/machine.ts`: original boot, loading, home, recovery, editing, preview, validation, feedback, theory, performance, interruption and content-error states, plus explicit calibration preparation/active/result states. `COUNT_IN` carries purpose. Saving is an independent `clean | pending | saving | failed` field.
- `src/app/sessionReducer.ts`: one command path for all editor inputs, read-only selection, ghost preview/commit, cancellation, orientation interruption, and validated document replacement. `LOAD_DOCUMENT` retains and increments the session serial. Run IDs contain document ID and serial, so reloading the same document at revision 0 cannot accept the old run's callback.
- `src/app/selectors.ts`: document, edit/history availability, coverage, event labels, active run/save request, objective-based next unlock.
- Async audio, validation and saving completions require both expected request `runId` and current `documentRevision`. Stop, navigation, document replacement, editing during pending validation, and newer requests invalidate stale completion paths.
- `VALIDATION_DONE` queues a save of objective success before explanation review. Existing objective success is never revoked by explanation or tap results. L4/L5 retain the learner's accepted snapshot. Model/A-B previews use optional validated `previewEvents` in an independently frozen run snapshot while preserving the editor document and its tempo.

## UI and adapter handoff

Use `useReducer(sessionReducer, createSessionState(document, puzzle))`. Use `LOAD_DOCUMENT { document, puzzle? }` for later document switches instead of reinitializing the reducer; serial preservation matters for stale callback protection. `state.editor.document` is the current document; UI must not mutate it.

Editor intents: `EDIT_COMMAND { command, updatedAt? }`, `SELECT_EVENT { id? }`, `PREVIEW_COMMAND { command }`, `COMMIT_GHOST { updatedAt? }`, `CANCEL_GHOST`, `POINTER_CANCEL`, `LOST_POINTER_CAPTURE`, `ORIENTATION_CHANGE`. The selection field is `selectedEventId`. Bare-domain alternatives are `createEditor`, `executeCommand`, and `previewCommand`; command payloads use exact source names `startTick` and `durationTick`.

Playback intents: `PLAY_PREVIEW { previewEvents? }`, `PLAY_PERFORMANCE`, `START_CALIBRATION`, `STOP`, `HIDDEN`, `INTERRUPTED`. All readiness/completion/tap messages carry `{ runId, documentRevision }`. `AUDIO_READY` may supply `{ rawStartMs, rawEndMs, barEndMs }`; performance/calibration collection requires those bounds. `BAR_COMPLETE` does not score; `INPUT_WINDOW_CLOSED { nowMs }` must pass the close-time guard before a calculation effect is emitted. Performance confidence supports `normal`, `practiceOnly`, `lowConfidence`, `invalidated`, `notApplicable`.

The reducer owns immutable snapshot creation and request identity. Audio owns actual context unlock, scheduling, stop/disposal and clock-derived callbacks. Storage owns durable writes and lease/fencing. `effects` explicitly request `prepareAudio`, `stopAudio`, `validate`, `save`, `calculatePerformance`, or `calculateCalibration`; adapters must execute each request once and dispatch the matching completion. Starting audio and submitting request an immediate draft save with its own identity. Invalidating an in-flight save on stop/back/close renews its request; it cannot leave a pending status with no request. `saving=pending` alone never means persisted.

S11 must connect debounce/checkpoints and immediate save requests, validate restored progress, and coordinate destination navigation with the prior draft's actual transaction result. A failed save retains the current document in memory and exposes `storageError`; UI must provide export. This stage does not simulate successful writes. In-memory undo history is intentionally not restored after reload.

Root owns global `progress.md`/`handoff.md`, UI implementation and later adapters to avoid concurrent edits. Independent read-only review found two boundary defects: retained finished runs blocked direct retry, and replacing a run could orphan an in-flight save. Both were fixed and regression-tested before final handoff. No known failing automated gate remains.
